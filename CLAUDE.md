# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Layout

The repo root holds planning docs; the app is in `site/` (Next.js 16, React 19, TypeScript, GSAP, Lenis, Zod). Run every npm command from `site/`.

- `brief.md`: the source of truth for story, design direction ("Architectural Editorial": ivory/ink/copper palette, serif display + sans body) and content rules. Read it before changing copy or visuals.
- `scroll-plan.md`, `story-review.md`: chapter-by-chapter motion plan and review notes for the home page.
- `columbus-roofer-sitemap.csv`: the 24-page spec the site was built from.
- `SKILL.md` at the root is the `scrollytelling` skill file, not project docs.

`site/AGENTS.md` warns that this Next.js version has breaking changes; read the relevant guide in `site/node_modules/next/dist/docs/` before writing Next-specific code. Typed route helpers such as `PageProps<"/locations/[slug]">` and `LayoutProps<"/">` are global and are generated by `next build`/`next dev`.

## Commands (run in `site/`)

```bash
npm run dev            # http://localhost:3000
npm run build          # also regenerates route types
npx tsc --noEmit       # typecheck
npm run lint           # eslint
npx next start -p 3100 # serve the production build
```

There is no test suite. Verify changes with `tsc`, `lint`, `build`, then look at the page in a browser (the intro and scroll animations only show on a real clock).

## Content rules (important)

The company is a placeholder ("Your Roofing Company"). **Never invent** ratings, reviews, licences, insurance, response times or local facts. All company details live in `site/lib/site.ts` (marked PLACEHOLDER); sample content in `site/lib/data.ts` and `site/lib/roof-materials.ts` must be flagged with `<Notice>` (from `components/ui.tsx`), which renders only while `site.placeholderContent` is true.

`site.live` (env `NEXT_PUBLIC_SITE_LIVE=true`) gates indexing: while false, `robots.ts` disallows everything and the layout emits `noindex`. The `RoofingContractor` JSON-LD in `app/layout.tsx` is also emitted only when live, so placeholder phone/email never reach search engines. Do not add `aggregateRating` markup without real, visible reviews.

## Architecture

**Single data source.** Services, areas, projects, reviews and process steps come from `lib/data.ts`; `lib/site.ts` holds company details and the nav. Dynamic routes (`app/roofing-services/[slug]`, `app/locations/[slug]`) use `generateStaticParams` with `dynamicParams = false`, and `app/sitemap.ts` is built from the same data. Adding a page usually means touching data, the route, and the sitemap.

**Motion engine = markup hooks + one component.** `components/Motion.tsx` (mounted once in `app/layout.tsx`) lazy-loads GSAP/ScrollTrigger/Lenis and drives everything from `data-*` attributes in the markup: `data-reveal`, `data-split` (word-mask headline), `data-parallax`, `data-progress`, plus `.hero`, `.roofline`, `.chapters`. To animate something, add the attribute rather than new JS. It re-runs per `pathname`, adds the `js-motion` class to `<html>` (CSS hides reveal targets only when this class is present), and does nothing under `prefers-reduced-motion`.

**Entry curtain.** `components/Intro.tsx` is CSS-only and self-hiding so it can never trap a visitor. An inline script uses `sessionStorage` to add `no-intro` to `<html>` on repeat loads. Its timing is coupled to `INTRO_DELAY` in `Motion.tsx` (the hero timeline waits for the curtain); keep the CSS keyframe delays in `globals.css` (`.intro`) and that constant in sync.

**Roofline SVG** (`Roofline` in `components/ui.tsx`) renders two overlays: `.roofline` (drawn by scroll in `Motion.tsx`) and `.roofglint` (CSS-only travelling light). Motion selects `.roofline path`, so keep the glint in a separate `<svg>`.

**Estimate flow.** `components/EstimateForm.tsx` (3-step, client) and `app/api/estimate/route.ts` both validate with the shared Zod schema in `lib/estimate.ts`; the server re-validates. The route enforces same-origin, JSON content type, 8 KB body cap, an in-memory per-IP rate limit, and a honeypot (`website` field). Leads are forwarded to `ESTIMATE_WEBHOOK_URL` (https only). **In production with no webhook set it returns 503**, so the deployed form currently cannot submit; set that env var in Vercel. `app/request-estimate/page.tsx` reads `?roof=<material>.<color>` from the roof visualizer and prefills the message via an allowlist lookup (`roofLabel`), never echoing raw query text. Reading `searchParams` makes that route dynamic.

**Security headers** (CSP, HSTS, frame/CORP policies) are set in `next.config.ts`. CSP allows `'unsafe-inline'` scripts because Next and the intro script use inline code; anything new loaded from another origin (fonts, analytics, images) needs a CSP update.

**Styling** is one global stylesheet, `app/globals.css`, with design tokens as CSS variables (`--copper`, `--ink`, `--bone`, ...); there is no CSS-in-JS or Tailwind. The header switches to the burger menu at `max-width: 1340px`; adding top-level nav items can overflow it.

**Images.** Photos are in `public/images/` (served through `next/image`). `public/images/samples/*.svg` are drawn placeholder illustrations used by the before/after slider (`components/BeforeAfter.tsx`, which passes `unoptimized` for `.svg`). Replace them with real job photos.
